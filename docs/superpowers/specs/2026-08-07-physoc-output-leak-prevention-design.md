# Physoc 回答输出泄漏修复设计

## 目标

用户端最终回答只包含自然语言答案，不显示以下内部信息：

- Physoc/Ollama 事件字段：`model`、`created_at`、`response`、`done`。
- 检索元数据：文件名、`source`、`classification`、`rank`、`score`。
- Agent 内部调查摘要、检索轮次和来源比较信息。

后端内部继续保留检索命中、引用、分数和审计记录，管理端治理功能不受影响。

## 根因

### 嵌套事件 JSON

正常 Physoc SSE 事件由外层 JSON 的 `response` 字段承载回答片段，当前解析器能够正确提取该字段。但是部分内网代理会把原始 Physoc/Ollama 事件 JSON 序列化后再次放入外层 `response` 字符串。当前解析器把这个字符串视为普通回答，因此整个 `{model, created_at, response, done}` 对象进入最终答案。

第一阶段修复能够处理“单条外层 SSE 事件的 `response` 包含完整内层事件 JSON”的情况，但线上进一步发现代理可能把同一个内层事件 JSON 拆进多条外层 SSE 事件。逐条解析时，每个 `response` 都只是 JSON 片段，只有完成累积后才形成合法对象，因此逐事件解包无法识别，拼接后的事件元数据仍会出现在答案末尾。

### 检索元数据复述

`build_knowledge_context` 当前把文件名、分类、排名和分数直接写入模型提示词，`build_prompt` 还把 Agent 调查摘要发送给模型。较小的本地模型不会稳定遵守“不要输出元数据”的提示词规则，可能直接复述模型输入中的内部字段。

## 方案选择

采用“协议边界严格兼容 + 模型上下文最小化”的方案。

没有采用单纯输出正则清洗，因为它可能删除文档正文中合法出现的字段名称，也无法可靠处理跨事件分段的嵌套 JSON。没有采用只强化系统提示词的方案，因为当前问题已经证明小模型不能稳定遵守该约束。

## Physoc 协议边界

`collect_physoc_response` 继续接受当前标准 SSE 结构。对每个事件的外层 `response` 字符串执行一次受限检查：

1. 普通自然语言字符串按现有逻辑累积。
2. 如果字符串完整解析为对象，并且对象同时包含合法的字符串 `response` 与布尔值 `done`，则把它识别为一层嵌套事件。
3. 最多解包一层，不递归解析更深层对象。
4. 嵌套对象存在 `model` 时必须是非空字符串，并与期望模型及外层模型一致。
5. 内外同时提供 `done` 时必须一致，避免代理产生歧义终止状态。
6. `created_at` 及其他不影响回答的附加字段可以存在，但绝不进入返回文本。
7. 嵌套结构无效、模型冲突、终止状态冲突或嵌套 `response` 仍是事件对象时，抛出 `PhysocStreamError`。

### 跨 SSE 分片的最终组装检查

完成外层 SSE 事件累积后，在返回答案前执行一次严格的最终组装检查：

1. 如果累积结果是普通自然语言，保持原样。
2. 如果累积结果完整解析为一个 Physoc 事件对象，则提取其 `response`，并执行与逐事件解包相同的 `model`、`done`、字段类型和嵌套深度校验。
3. 如果自然语言正文后紧跟一个或多个完整 Physoc 事件对象，则保留自然语言前缀，只把合法事件对象中的 `response` 追加为答案正文。
4. 如果整个结果由连续多个 Physoc 事件对象组成，则按顺序拼接各对象的 `response`，要求只有最后一个对象可以声明 `done=true`。
5. 事件对象可以跨任意外层 SSE 分片边界；识别依据是最终组装后的严格 JSON 语法和 Physoc 字段契约，而不是分片位置。
6. 只处理协议对象；合法文档正文中的普通 JSON 对象在不满足 Physoc 字段契约时保持不变。
7. 不使用正则删除字段名，也不扫描并删除任意花括号文本。

最终检查仍然只允许一层协议包装。事件对象的 `response` 再次包含 Physoc 事件对象时拒绝处理，避免递归解包和隐藏 payload。

该错误继续由 LLM Provider 转换为用户安全的“大模型返回格式异常”，原始 payload 不进入日志消息、HTTP 响应或聊天记录。

## 模型可见上下文

模型提示词只包含：

- 用户问题。
- 检索模式。
- 编号后的纯知识片段正文。
- 必要的最近会话历史。

模型提示词不再包含：

- 文件名和来源 ID。
- 分类标签。
- 检索排名、融合分数或重排分数。
- Agent 调查摘要、来源数量、来源名称或内部工具步骤。

`KnowledgeSearchHitModel`、Citation、AgentStep 和 Retrieval Audit 中的内部字段保持不变。改动仅发生在发送给大模型的序列化视图，避免影响权限判断、检索排序、管理端审计和质量评测。

## 数据流

```text
知识库检索结果
  -> 后端内部完整命中对象（保留来源、分类、排名、分数）
  -> 模型可见纯文本片段（删除内部元数据）
  -> Physoc SSE
  -> 严格外层/单层嵌套事件解析
  -> 跨 SSE 分片的最终组装检查
  -> 自然语言回答
  -> 用户端
```

## 错误处理

- 标准 SSE 行为保持兼容。
- 单层嵌套事件正确提取内层 `response`。
- 跨多条外层 SSE 事件拆分的内层 JSON 在最终组装阶段正确提取 `response`。
- 自然语言正文末尾的合法 Physoc 事件对象不会把 `model`、`created_at` 或 `done` 带入答案。
- 普通自然语言和不满足 Physoc 契约的合法 JSON 文档正文保持不变。
- 内外模型或 `done` 冲突时拒绝整个回答，不猜测使用哪一层。
- 超过一层的事件包装拒绝处理，避免递归解析和隐藏 payload。
- 无效格式使用现有安全错误文案，不能回显原始事件内容。
- 不使用通用正则删除最终回答中的单词，避免破坏合法文档答案。

## 测试范围

- 标准 Physoc SSE 仍只返回 `response` 文本。
- 单层嵌套事件能够跨多个 SSE 事件累积答案。
- 被拆成多个外层 `response` 片段的单个内层事件能够在最终组装后解包。
- 正常答案加末尾事件 JSON 时，仅返回正常答案和事件的 `response` 正文。
- 连续事件 JSON 按顺序拼接正文，并拒绝非法终止顺序。
- 嵌套事件的 `model`、`created_at` 和 `done` 不进入答案。
- 内外模型不一致、`done` 不一致、二次嵌套和无效字段被拒绝。
- `build_knowledge_context` 只包含片段正文，不包含文件名、分类、排名和分数。
- `build_prompt` 不包含 Agent 调查摘要和内部来源信息。
- Physoc Provider 最终 `ChatMessageModel` 只包含自然语言回答。
- 后端完整测试、Ruff、ty 和部署契约继续通过。

## 版本规则

本次补充修复只修改后端。完成实现和验证后，将后端版本从 `0.1.10` 独立提升到 `0.1.11`；用户端与管理端版本保持 `0.1.1`。
