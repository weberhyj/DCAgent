# 知识库新文档默认公开设计

## 目标

将后续新上传知识库文档的默认分类统一为“公开”，并让默认检索权限标签使用同一个值，避免文档已成功解析但因默认分类与检索过滤条件不一致而无法命中。

## 范围

- 新上传文档在未显式指定分类时使用“公开”。
- 根目录、后端和 Ubuntu 部署环境模板中的 `RETRIEVAL_PERMISSION_TAGS` 默认使用“公开”。
- 部署文档、README 示例及相关自动化测试同步使用新的默认值。
- 现有数据库记录、已上传文件和已构建索引不做迁移；管理员可以删除后重新导入。
- 调用方显式提交其他分类时继续保留该分类，不强制覆盖。

## 数据流

1. 客户端上传文件且不传 `classification`。
2. API 将文档分类保存为“公开”。
3. 解析完成后文档状态变为“已索引”。
4. 默认检索权限标签同为“公开”，Legacy/Shadow 路由不会因默认值不一致过滤该文档。
5. 检索命中后，证据交给配置的大模型接口汇总回答。

## 配置和兼容性

- 配置名称保持 `RETRIEVAL_PERMISSION_TAGS` 不变，仅修改示例和部署模板的默认值。
- 使用自定义权限标签的内网环境不受影响；实际 `.env` 中的显式配置优先。
- 不自动修改现有 `.env`，部署者升级后需要确认实际环境配置是否与新导入文档分类一致。
- 不新增数据库迁移，也不批量修改历史文档分类。

## 测试

- API 上传测试验证未传分类时返回“公开”。
- 检索回归测试验证默认公开文档在默认公开权限范围内可被命中。
- 显式分类上传测试继续验证调用方传入的分类不会被覆盖。
- 环境模板和部署文档检查验证默认权限标签统一为“公开”。

## 验收标准

- 后续上传文档默认显示为“公开”。
- 文档完成索引后，使用默认部署配置可以检索到相关内容。
- 现有文档保持原分类不变。
- 相关后端测试、格式检查和配置检查通过。
