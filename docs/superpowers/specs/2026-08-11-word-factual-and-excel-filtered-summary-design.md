# Word 精确事实与 Excel 条件汇总问答设计

## 状态

本设计在 2026-08-11 的对话中确认，作为现有 Excel/CSV 结构化聚合和企业级知识库问答设计的增量修订。它只描述“问题分流、证据范围和回答约束”的补强，不改变 ClickHouse 作为 Excel 权威数据源、Qdrant 作为文档语义检索源的职责边界。

相关设计：

- `docs/superpowers/specs/2026-07-21-excel-structured-aggregation-design.md`
- `docs/superpowers/specs/2026-07-24-enterprise-knowledge-base-qa-design.md`

## 背景

当前系统存在两类可复现问题：

1. 用户按 Excel 某个列的值筛选，再询问其他列的汇总时，问题可能未被结构化解析，随后回退到普通 RAG 并命中无关 Word 文档。
2. Word 中同一段包含年龄、性别、职务等多个事实时，用户只问年龄，回答仍可能把其他字段一起带出。

共同根因是问题路由和证据范围不足以表达“本次问题允许回答哪些事实”。大模型只能依据收到的证据组织语言，不能单独承担字段选择、精确统计或事实边界控制。

## 目标

- Excel 条件汇总始终走已发布的 ClickHouse 数据，不使用文本切片估算。
- 支持一个筛选条件下的单指标和多指标汇总。
- Word 精确事实问题只回答请求字段，例如“张三几岁”只返回年龄。
- 普通文档问答和开放式总结继续使用 Qdrant 混合检索、BGE Reranker 和内网大模型。
- 结构化或精确事实问题解析失败时澄清或明确不可用，禁止回退到无关文档。
- 大模型只负责受控表达，不负责选择字段、执行 SQL 或修改统计结果。

## 非目标

- 不把 Word 全部内容强制转换成 Excel。
- 不把十几万条 Excel 行数据放入 Qdrant 或大模型上下文。
- 不允许用户或模型提交任意 SQL。
- 不要求所有开放式文档问题都变成结构化字段问题。
- 不在本次设计中实现 Word 表格的复杂跨行统计；Word 表格仍可检索、引用和总结。

## 统一问题路由

问题在进入 Embedding/Reranker 或大模型前，先经过规则优先的路由器。模型可以辅助复杂意图识别，但不能拥有最终执行权限。

| 路由 | 典型问题 | 权威证据 | 最终回答 |
| --- | --- | --- | --- |
| `excel_filtered_aggregate` | 地区为华东的销售额总和 | ClickHouse 查询结果 | 确定性模板或结果表 |
| `excel_multi_aggregate` | 地区为华东的销售额、成本、利润汇总 | ClickHouse 查询结果 | 多指标结果表 |
| `word_factual` | 张三几岁 | Word 字段级事实 | 字段模板或受限表达 |
| `document_qa` | 报销流程是什么 | Qdrant 证据包 | Reranker + 大模型 |
| `summary/compare` | 介绍张三、对比两份制度 | 分层文档证据 | 大模型综合回答 |
| `clarification` | 数据集、字段或聚合口径不明确 | 元数据候选 | 澄清问题 |

只要问题已经识别出 Excel 数据集/列或 Word 实体/字段，后续解析失败不得转入 `document_qa`。

## Excel 条件汇总

### 支持范围

支持以下形式：

```text
地区为华东的销售额总和
部门=研发部的费用平均值
项目为A的合同金额最大值
地区为华东的销售额、成本、利润汇总
```

支持的聚合词包括：`汇总`、`统计`、`合计`、`总和`、`求和`、`平均`、`平均值`、`均值`、`数量`、`计数`、`多少条`、`最大`、`最高`、`最小`、`最低`。

### “汇总”口径

当用户只说“汇总”而没有指定平均、最大或最小时，默认：

- 对筛选结果中所有管理员确认 `allowAggregate=true` 的整数/定点小数列执行 `sum`；
- 同时返回匹配行数；
- 非数值列不进行隐式求和；
- 如果可聚合列超过配置上限，返回候选列并要求用户选择。

明确说“平均、最大、最小”时使用对应算法。多指标结果必须返回列名、聚合函数、值、匹配行数、有效值数和空值数。

### 查询安全

- 数据集、工作表、筛选列和指标列只从已发布 schema 解析。
- 筛选列必须允许 `allowFilter`，指标列必须允许 `allowAggregate`。
- SQL 由服务端生成，值使用参数绑定，列名和函数使用白名单。
- 查询账户只读，并保留执行时间、内存和结果行数限制。
- ClickHouse 超时、不可用或数据未发布时返回明确的结构化错误，不回退 Word。

### 回答

纯 Excel 汇总不调用大模型计算。后端先得到不可变的结构化结果，再选择模板或让大模型只做解释；模型不得修改数字、筛选条件或数据版本。多指标结果使用表格 artifact 或等价结构化响应。

## Word 精确事实问答

### 事实元数据

DOCX 解析保留标题、段落、列表和表格行，同时从常见键值表达式中提取事实：

```json
{
  "entity": "张三",
  "field": "年龄",
  "value": "28岁",
  "source_id": "source-personnel-docx",
  "chunk_id": "chunk-...",
  "locator": {"paragraph": 12}
}
```

事实字段使用可配置同义词，例如：`几岁/多大 -> 年龄`，`什么职位/担任什么 -> 职务`。无法可靠提取为字段的叙述文本仍作为普通文档片段保留。

### 精确问题流程

```text
“张三几岁”
→ 识别 entity=张三、field=年龄
→ 只检索授权范围内的年龄事实
→ 对候选事实去重和冲突检查
→ 直接返回“张三，28岁”或受限表达
```

要求：

- 精确事实问题只允许输出目标字段。
- 不执行当前的无条件相邻片段扩展。
- 不执行会使用默认 Embedding 的全文二次 `inspect_document`。
- 实体重名或同一字段存在冲突时，返回候选来源并要求澄清。
- 没有目标字段证据时明确回答未找到，不能用性别、职务等其他字段推断年龄。
- 单一事实优先使用模板，不必调用大模型。

### 开放式问题

“介绍张三”“张三有哪些任职经历”等开放问题继续走普通文档 RAG。大模型只能接收经过权限过滤、去重、重排和预算控制的证据包，并在引用支持范围内综合回答。

## 大模型和 Reranker 的职责

- Embedding：召回候选，不决定答案范围。
- BGE Reranker：在候选集内排序，不执行统计、不抽取最终字段。
- ClickHouse：执行 Excel 完整数据的过滤和聚合。
- Word 事实抽取器：确定实体、字段和值的边界。
- 大模型：对允许回答的事实做自然语言表达或综合总结。
- 回答校验器：检查精确问题是否出现未请求字段，检查结构化数字是否被改写。

生产路径中，Reranker 后的相邻片段扩展必须服从路由类型和证据预算；`word_factual` 禁止扩展，`document_qa` 才允许受限扩展。

## 失败和降级

- Excel 识别到数据集但字段/口径不完整：返回澄清，不检索 Word。
- Excel ClickHouse 超时：返回结构化数据暂时不可用，不使用切片估算。
- Word 识别到实体但没有目标字段：返回未找到，不扩大到其他字段。
- Word 实体或字段有歧义：返回候选项，请用户选择。
- Reranker 过载：普通文档问答可使用受控降级排序；精确事实问答不能扩大候选范围。
- 大模型不可用：精确事实和纯 Excel 汇总仍可返回确定性结果；普通综合问题明确返回模型不可用。

## 数据迁移和部署

- 现有已发布 Excel 数据不需要重新上传；扩展多指标查询和路由后直接使用现有 ClickHouse 发布版本。
- 已有 Word 文档需要按新解析器和事实元数据重新解析、切片、Embedding 并发布新索引版本。
- 新索引完成验证前继续提供旧文档索引；通过发布指针原子切换。
- 生产部署仍使用现有 Ubuntu/Supervisor、ClickHouse、Qdrant、Embedding 和 llama.cpp BGE Reranker 拓扑。

## 测试和验收

### Word

- `张三几岁` 只返回年龄，不出现性别或职务。
- `张三是什么职位` 只返回职务。
- `介绍张三` 可以返回多个有证据字段。
- 同名实体要求澄清。
- 年龄和性别位于同一原文段落时，精确问年龄仍只能返回年龄。
- 相邻片段包含性别时，精确问年龄不能把性别带入答案。

### Excel

- 地区为华东的销售额总和与 Python/Decimal 基准一致。
- 地区为华东的销售额、成本、利润汇总返回多个指标和匹配行数。
- “汇总”默认求和；明确平均/最大/最小时使用指定算法。
- 字段、工作表或数据集歧义时返回澄清。
- ClickHouse 不可用时不出现 Word 片段。
- 100,000 行以上数据查询不把全量行加载到 Python 或大模型上下文。

### 检索和回答

- Agent 审计记录路由类型、数据集/实体、目标字段、候选来源、降级原因和回答校验结果。
- 普通文档问答继续验证 BGE Dense/Sparse、RRF、BGE Reranker 和引用定位。
- 结构化数字 100% 与基准结果一致；精确事实回答不得出现未请求字段。

## 分阶段实施

1. 扩展 Excel 聚合意图、`汇总` 口径、多指标计划和严格不回退规则。
2. 增加统一问题路由和回答契约。
3. 增加 DOCX 结构化解析、事实元数据和精确事实路由。
4. 限制精确事实路径的相邻扩展和二次 inspect，补充输出校验。
5. 重建 Word 索引，执行回归、权限和性能验收。
