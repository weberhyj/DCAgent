# 问候意图直达欢迎词设计

## 背景

当前所有用户输入都会进入结构化查询或知识库检索链路。对于“你好”这类不需要知识证据的问候，检索结果通常为空，LLM Provider 随后直接返回“未检索到足够依据”，因此用户看不到欢迎词，且大模型不会被调用。

## 目标

- 纯问候消息直接返回固定欢迎词。
- 问候消息不执行知识库检索、不检查文档、不调用大模型。
- 正常知识问题、统计问题和带实质问题的复合消息保持现有链路。
- 问候回复仍生成完整 Agent 审计记录，便于后台追踪。

## 非目标

- 不实现通用闲聊能力。
- 不让大模型自由生成欢迎词。
- 不修改前端页面布局或首页静态欢迎标题。
- 不改变结构化统计、混合检索、Reranker 或 Physoc DeepSeek 接口。

## 方案比较

### 方案 A：Agent 入口进行确定性意图判断（采用）

由 `ReadOnlyKnowledgeAgent` 提供问候识别和结果构造能力。SQL 与内存 Repository 在结构化查询和检索之前调用该能力，因此行为一致，并且纯问候不会访问结构化数据目录。

优点：后端统一、无需模型、延迟低、可审计、不会依赖知识库内容。缺点：只支持明确列入规则的问候表达。

### 方案 B：只修改大模型提示词

让模型自行判断问候并生成欢迎词。

不采用：当前 Provider 在无知识片段时会提前返回，提示词不会执行；同时增加不必要的模型调用和输出不确定性。

### 方案 C：前端拦截问候

由 Vue 前端直接插入欢迎消息。

不采用：API 调用方会得到不同结果，审计记录缺失，并且业务规则会散落在客户端。

## 行为设计

系统对输入执行轻量规范化：去除首尾空白，将字符转为小写，并忽略空格及常见中英文句末标点。规范化后的完整输入必须精确匹配问候白名单，才进入欢迎分支。

首批支持：

- `你好`
- `您好`
- `嗨`
- `哈喽`
- `在吗`
- `你在吗`
- `你是谁`
- `介绍一下你自己`

例如，“你好！”会返回欢迎词；“你好，请问报销制度是什么”包含实质问题，不会被问候分支截获，仍走原有知识问答链路。

固定欢迎词为：

> 您好，我是 DCAgent 企业知识库智能助手。您可以向我询问 Word、Excel、PDF 等知识库资料中的内容，我会检索相关依据并为您汇总回答。

## 数据流

1. Repository 接收消息，先调用 `ReadOnlyKnowledgeAgent` 的问候识别入口。
2. 命中时直接构造助手消息和 `respond_greeting` 审计步骤。
3. 返回结果并按现有 Repository 逻辑持久化用户消息、助手消息和 Agent Run。
4. 未命中时才依次尝试现有结构化统计服务和 LangGraph 知识检索流程。

## 审计与错误处理

- 欢迎分支的 `evidence_count` 和 `source_count` 均为 `0`。
- 只记录一个已完成的 `respond_greeting` 步骤。
- 欢迎分支不访问结构化目录、知识检索服务或模型服务，因此不会产生这些依赖的超时或 502。
- 空输入仍由现有 API 校验处理，不属于问候意图。

## 测试设计

- “你好”返回固定欢迎词。
- 带空格和标点的“您好！”也能识别。
- 问候分支不会调用检索、文档检查或 LLM Provider。
- Agent Run 包含一个 `respond_greeting` 步骤，证据数和来源数为零。
- “你好，请问报销制度是什么”不被误判，并继续调用现有检索链路。
- 运行后端相关测试、完整后端测试与 Ruff 检查。

## 验收标准

用户发送纯问候后，界面显示固定欢迎词；后台没有知识检索和模型调用；正常知识问答及结构化统计行为不变。
