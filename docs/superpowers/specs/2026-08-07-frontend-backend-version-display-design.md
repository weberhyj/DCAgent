# 前后端版本分区显示设计

## 目标

在两个独立页面中显示各自需要关注的版本信息：

- 用户端只显示用户端版本，例如 `v0.1.0`。
- 管理端只显示后端服务版本，例如 `v0.1.9`。
- 页面组件不重复硬编码版本号，版本显示始终跟随对应版本源。
- 版本获取失败不能影响问答、知识库管理或其他业务功能。

示例中的版本号是设计时的当前值。后续按仓库既有规则升级版本后，页面应自动显示升级后的值。

## 方案选择

采用“用户端构建时注入、管理端运行时读取后端”的方案。

用户端版本来自 `frontend/package.json`。Vite 在构建时把该值注入用户端应用，页面只渲染带 `v` 前缀的语义化版本号。这样用户端版本与部署产物一一对应，也不依赖后端接口。

后端版本继续以 `backend/app/__init__.py` 的 `__version__` 为唯一来源。后端提供只读版本接口，管理端启动后调用该接口，并在管理布局中显示返回的后端版本。管理端自身的 `package.json` 版本不作为页面上的后端版本展示。

没有采用以下方案：

- 通过部署环境变量分别填写版本：容易漏配，并可能与实际代码版本不一致。
- 两个页面都从后端读取版本：会让用户端版本错误地依赖后端部署状态。
- 在 Vue 组件中直接写死版本：每次升级都需要同步修改多处，容易产生漂移。

## 页面与组件边界

### 用户端

`ConversationSidebar.vue` 负责用户端侧栏展示，在侧栏底部以弱化的小字号显示用户端版本。组件只消费构建时提供的只读版本常量，不执行网络请求。

显示内容只有：

```text
v<用户端版本>
```

不显示“前端”或“后端”字样，也不显示管理端或后端版本。

### 管理端

`AdminLayout.vue` 负责管理端全局布局。后端版本显示在顶部服务状态区域，与“服务运行中”状态关联但不替代健康状态。

显示内容为：

```text
v<后端版本>
```

管理端使用一个小型、独立的版本读取服务或 composable 管理请求状态，布局组件只负责展示。

## 后端接口

新增无鉴权只读接口：

```http
GET /api/version
```

成功响应：

```json
{
  "version": "0.1.9"
}
```

接口直接读取 `backend.app.__version__`，不读取环境变量，不访问数据库，也不执行外部依赖检查。它应在后端其他依赖处于降级状态时仍可返回版本。

## 数据流

用户端数据流：

```text
frontend/package.json -> Vite 构建常量 -> ConversationSidebar -> vX.Y.Z
```

管理端数据流：

```text
backend/app/__init__.py -> GET /api/version -> 管理端版本状态 -> AdminLayout -> vX.Y.Z
```

## 失败处理

- 用户端构建时必须能读取有效语义化版本；读取失败应使构建失败，避免发布未知版本产物。
- 管理端请求失败、响应格式错误或超时时显示 `版本未知`。
- 管理端版本请求失败不弹出全局错误提示，不阻塞路由渲染，也不改变服务健康状态。
- 页面卸载后不再写入组件状态，避免异步请求产生无效更新。

## 测试范围

- 验证 Vite 注入值来自 `frontend/package.json`。
- 验证用户端侧栏只显示用户端版本，不出现后端版本标签。
- 验证 `/api/version` 返回后端 `__version__`，且响应结构固定。
- 验证管理端成功获取后显示后端版本。
- 验证管理端接口失败时显示 `版本未知`，其他布局内容仍正常渲染。
- 运行前端、管理端构建与现有版本契约测试。

## 版本升级规则

本次实际修改到的应用按照仓库现有独立版本规则分别执行 patch 升级。页面不依赖固定示例值，因此升级后会自动显示新的用户端或后端版本。
